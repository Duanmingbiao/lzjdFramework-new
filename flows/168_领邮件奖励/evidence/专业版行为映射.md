## 3. 邮件调用链与映射

专业版静态调用链：root.728 → GK.Find2 / GK.FindUB2 → Find2封装 → 原生FindMultiColor；点击与等待经LuaAuxLib；计时重置经root.811。FindUB2按数组顺序优先返回第一项命中。封装对应关系来自旧项目保留的公共调用控制流摘录，本轮没有重跑原型提取。

新设计：任务调度 → 任务分派 → 执行邮件任务 → 入口识别循环 → 领取循环 → 可选消息循环 → 返回统一结果 → 公共返回大厅 → 统一提交。恢复时从邮件入口重跑，保存当前阶段用于诊断，不承诺从被打断的点击指令继续。

表中“全屏”为新项目标准范围0,0,719,1279；原调用是0,0,0,0全屏语义。原始主色均含-101010容差；完整偏色串必须从附属JSON读取，不能只用主色识别。方向1，相似度取专业版初始化0.9。

关键顺序：领取 → 奖励弹窗 → 普通弹窗 → 空状态 → 局部5秒判断，是多个独立If，不改成ElseIf优先链。

领取5秒从进入领取阶段开始，动作不会刷新它；公共“进展计时”是另一只时钟。消息阶段只有关闭普通弹窗刷新局部起点，打开消息不会刷新。消息逻辑的反编译嵌套不可靠，采用保留指令摘录的跳转解释，仍需实机核对。

入口直接无奖励是独立提前出口，即使配置自动阅读也不进入消息分支。若要“无奖励也自动阅读”，需以后明确改变需求；当前设计保留专业版原顺序。

“手动阅读”在此表示不自动读取消息，不自行增加暂停等待用户或无限等待阅读的流程。
